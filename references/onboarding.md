# 首次初始化、偏好与后续调用

安装只是把完整 Skill 放到客户端可发现的位置；Skill 不带安装时弹窗，也不会自行运行。第一次在某个项目调用时，由助手先完成下面的初始化。只要求安装/升级/评审 Skill 时不启动初始化或新实验。

## 第一次：短问答，保存一次

先确认当前工作目录是用户愿意保存实验的地方；没有文件能力就说明无法持久保存偏好。检测当前客户端、文件读写、图像和浏览器测试能力、可用的托管工具；能确定的事实直接告诉用户。仅对未确定或需要选择的内容提问，尽量合并成一次简短问答：

1. 使用单个独立实验，还是持续增加实验的分类目录网站？推荐目录站适合多个实验；一个 HTML 也可以包含主页、目录、题页和实验多个视图，页面数不等于文件数。
2. 除默认本地 HTML 外，是否还需要在线访问链接？选项只列当前可用的发布渠道和“暂不需要”。Codex 的 Sites、WorkBuddy 的网站应用/轻量发布、Kimi 的 Build 等是不同工具；没有检测到或只有文档证据时说明待核验，不承诺已可发布。
3. 当前助手是什么、实验保存在哪里？已知当前是 Codex/WorkBuddy/Kimi 时无需重复问品牌。含糊的“Kimi”要区分桌面/网页 Work 和 Kimi Code，因为安装、文件访问与发布能力不同。默认保存在所选项目的 experiments/，需要已有站点集成时再索取其地址或必要源码。

明确告诉用户：无论是否选在线链接，确认方案并制作后都会交付本地自包含 HTML，可在浏览器直接打开。源码目录可同时保留；在线版需要额外核验当前账户、额度、受众和工具。初始化没有题目时再请用户上传；已附题则保存偏好后直接进入阶段 A，不让用户重复上传。

用户回复之后保存项目根 `.physics-inquiry-web.json`，不得把尚未回答的推荐项视为已选择。偏好只含 assistant_host、site_mode、hosting、output_dir 与 local_html=true；不保存账号、凭据或发布/设计确认。配置错误时保留原文件，说明具体字段并询问最小修复，不能悄悄恢复默认。迁移到不同客户端先检查能力，不静默改变偏好，也不代用作者的托管账号。

## 后续：直接题目，不重复开场

每次从当前项目配置读取偏好。有效配置存在且用户没说改设置时，直接接收新题 → 分类 → 物理分析 → 报告与逐屏效果图 → 等待本题报告确认。没有题目才索题。用户说“改成多实验目录”“这次只要本地”时先说明本次覆盖还是持久修改；只有明确要求长期改才更新配置。换新项目不扫描其他私人目录找设置，用户可指定复用已知配置。

保存偏好不能取消每道新题的设计确认。记住 hosting 也不等于每次可以公开发布；报告应写清目标站点及受众，后续按用户当前授权与宿主规则执行。额度不足或缺少工具时说明实际缺项，保留配置；用户可以在有额度的助手继续，不能声称另一个客户端生成/发布已通过。

## 可选的确定性保存工具

有 Python 时调用 `python3 scripts/preferences.py --project /absolute/project status` 读取。项目目录须事先存在；status 不创建文件。已收到选择后才调用 `init --assistant-host codex --site-mode catalog --hosting codex-sites`（这些只是命令示例，不是替用户选择）。现有配置用 update 只更改用户指定字段，例如 `update --hosting none`。参数详见 --help；工具只保存偏好，不检查托管能力、不问答、不生成实验、也不代表授权。

没有 Python 而有文件能力时，助手可按相同 schema 写 JSON：schema_version=1，assistant_host 为 codex/workbuddy/kimi/other，site_mode 为 single/catalog，hosting 为 none/codex-sites/workbuddy/kimi/other，output_dir 为项目内目录（默认 experiments），local_html 必须为 true。以工具实际输出 schema 为准。无持久文件能力时明确这轮只能在对话中记住选择，下次需要再次提供，不假装跨会话记忆。
