# 安装、第一次使用与分享

Physics Inquiry Web 是一份供助手使用的 Skill，不是网页内的自动识题服务。用户提供一道完整题目后，助手判断题型与适配度，整理物理分析、分类建议和逐屏设计报告；用户确认本题方案后，助手再制作中英双语交互实验。默认交付可在浏览器直接打开的本地 HTML；在线托管是可选项，须按当前客户端的实际工具和用户选择执行。

从 [GitHub 最新发行页](https://github.com/jiaweihuang1224-arch/physics-inquiry-web/releases/latest)下载完整附件 `physics-inquiry-web.zip`，也可用[直接下载地址](https://github.com/jiaweihuang1224-arch/physics-inquiry-web/releases/latest/download/physics-inquiry-web.zip)。公开 Release 下载不需要私有仓库访问权限或 GitHub 私有令牌。

## 安装完整包

解压完整 ZIP，保留 `SKILL.md` 所在的 `physics-inquiry-web/` 文件夹以及其中的 `assets/`、`references/`、`scripts/` 和其他文件。不要只复制 `SKILL.md`：它依赖包内的流程说明、图像参考和案例资源。

- **Codex：** 放入当前客户端支持的 Skill 目录。通用目录通常是 `~/.agents/skills/physics-inquiry-web/`。如果本机已通过 `~/.codex/skills/physics-inquiry-web/` 使用此 Skill，就在该目录原位更新完整文件，不要另建同名副本。新会话调用 `physics-inquiry-web`；若列表尚未刷新，可直接指定 `SKILL.md` 路径。
- **WorkBuddy：** 使用技能面板中当前可用的自定义技能导入入口，上传完整 ZIP；入口名称或位置变化时以客户端当前界面和官方说明为准。
- **Kimi Work：** 在当前技能或插件界面核对是否提供自定义包导入，再按实际入口操作；不要把技能市场搜索当成已导入自制包。
- **Kimi Code：** 将完整目录放到 `~/.kimi-code/skills/physics-inquiry-web/`，或放到项目支持的 `.kimi-code/skills/physics-inquiry-web/`，再按当前客户端的 `/skill:physics-inquiry-web` 入口调用。
- **没有 Codex 或客户端没有 Skill 导入：** 仍可使用具备项目文件读写和 HTML/JavaScript 能力的助手。把本包的 `SKILL.md` 及其引用的 `references/` 内容提供给助手，并让它在项目中生成本地 HTML；客户端不能读取项目文件时，需按其实际限制调整，不能假称已安装。

客户端入口和本包的实际验证记录见[平台与验证边界](platforms.md)。一般 Skill 文件夹不等于已上架官方技能商店。

## 第一次使用：初始化项目偏好

在准备保存实验的项目中调用 Skill，并发送：

> 使用 physics-inquiry-web，开始首次初始化。请先确认当前工具能力，询问我要做单实验还是分类目录、是否需要在线托管，以及本地保存位置。以后每道新题先给设计报告和逐屏效果图，等我确认这道题的方案后再制作；默认交付浏览器可直接打开的本地 HTML。

助手应先核实可用的文件、图像、浏览器和托管能力，再询问用户尚未决定的项目设置。只有用户回复后才保存该项目的 `.physics-inquiry-web.json`；安装本身不会弹出问答，也不会代替用户选择单实验/目录或托管方式。配置按项目保存，不自动从其他项目或客户端读取。若题目已随初始化消息附上，保存偏好后可直接进入该题的设计报告阶段，但仍须等待用户确认本题方案。

## 后续使用：每道新题先确认设计

在同一项目调用 Skill，并附上完整题干、题图、条件和全部选项：

> 使用 physics-inquiry-web，按当前项目设置分析我随消息附上的新题。请先判断题型与适配度，给出物理分析、分类建议、交互方案和逐屏效果图；等我确认这道题的方案后再制作。确认后交付中英双语、浏览器可直接打开的本地 HTML。

每道新题都要先提供设计报告并单独得到确认。初始化、记住托管偏好、之前题目的确认，都不构成新题的设计确认或公开发布授权。用户可以在报告阶段要求修改；待本题方案确认后再进入制作。交付本地 HTML 是默认结果，不需要选择托管；只有用户选择且当前工具确实可用时才继续在线发布。

单实验适合独立交付一题；分类目录适合逐步增加多个实验并按主题整理。目录站可以由一个 HTML 文件呈现主页、目录和实验视图，也可以采用多个本地文件，具体依设计报告决定。当前只有随包的平面镜案例提供可运行源码；助手可以为新题提出分类和模型，但这不等于包内预置了全题型实验库。

## 打开成品与可选开发工具

学生打开交付的本地 HTML 不需要 Python、Node 或命令行服务，使用浏览器即可。制作或修改源码时，助手可使用其实际可用的文件与代码工具；包内 `scripts/` 中的 Python/Node 工具用于案例导出、偏好管理和检查，是开发者的可选工具，不是打开实验网页的前置条件。运行脚本前要看它的具体参数与输出位置，不把固定平面镜案例导出工具当作任意新题的通用生成器。

如果工作环境无法访问文件或运行必要工具，助手应指出实际缺少的能力并说明这一轮能交付什么。可切换到确有权限和额度的工具继续，但不能编造生成、验证或托管成功，也不能借用作者的账号、网站或本机目录。
