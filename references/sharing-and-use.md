# 安装、第一次使用与分享

这是助手 Skill，不是网页里的自动识题服务。先安装完整文件夹，第一次调用时初始化偏好，上传题目后收到分类与实验设计报告，每屏效果图下面配功能与实现说明；确认本题报告后才生成实验。默认成品包含本地自包含 HTML，在线地址按所选平台额外交付。

## 安装一次

Codex：保持 physics-inquiry-web/SKILL.md 层级，将完整目录放入当前客户端支持的 Skill 目录。官方通用目录为 ~/.agents/skills/ 或项目 .agents/skills/；已有客户端在 ~/.codex/skills/ 发现本包时可原位更新，避免在多个目录放同名副本。新会话中明确调用 $physics-inquiry-web；未刷新时直接指定完整 SKILL.md 路径读取。

WorkBuddy：按官方“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”导入完整 ZIP。普通对话安装只搜索其技能市场，不会自动替你导入自制包；客户端入口有变化时按其官方说明操作。Kimi Work：插件/技能面板查看当前自定义导入能力，保留完整包，不把仅上传入口文字当成资源已安装。Kimi Code：放在 ~/.kimi-code/skills/physics-inquiry-web/ 或项目 .kimi-code/skills/physics-inquiry-web/，新会话以 /skill:physics-inquiry-web 调用。各平台是否真加载，检查其实际活动记录，不能凭回复“已读”就写全兼容。

私有 GitHub 仓库只有有权限的账号可下载；不把访问令牌写进命令、Skill 或分享文档。可以在仓库页面下载 ZIP，解压后将包含 SKILL.md 的文件夹命名为 physics-inquiry-web。普通源码仓库不等于已上架各客户端技能商店。平台与证据见 [platforms.md](platforms.md)。

## 第一次使用

在准备保存实验的空项目打开助手，发送：

> 使用 physics-inquiry-web，开始首次初始化。请先确认当前工具能力，询问单实验还是分类目录网站、是否额外需要在线链接；制作后默认保留可直接打开的本地 HTML。等我给题目后先出含逐屏效果图的设计报告，我确认后再制作。

助手检测能力、询问必要选择，回复后才保存当前项目 `.physics-inquiry-web.json`。安装不会自动弹出初始化，也不会预先替你选 Sites。配置按项目保存：在同一项目以后不用重填；新项目可明确指定复用已知配置，不能假装跨客户端自动同步。

## 以后直接调用并附题

Codex 可以发送“$physics-inquiry-web 按当前项目设置分析这道题”，并上传完整题干/题图。WorkBuddy 或 Kimi 使用自己客户端的技能入口/命令引用；@在一些客户端用于引用文件，并不是所有平台通用的 Skill 调用语法。题已给出就不会重复索题，按既有设置交报告；每道新题的报告仍需要确认。

若要改设置，直接说“以后改成分类目录站”或“这一次只交本地”。助手区分本次覆盖与长期偏好，不擅自发布。已选托管渠道缺工具/额度时如实说明，允许用户换有额度的助手继续，不编造链接或测试通过。

## 确认后的交付和参考工具

交付实验自包含 HTML、需要的源码/素材和测试说明；若选在线发布，再交实际可用 URL。普通多视图目录也能装进同一 HTML。固定平面镜案例可运行 `python3 scripts/export_single_html.py --output /absolute/experiment.html`，仅作为本例验证；新题不使用它冒充通用生成。`node scripts/verify_reference.mjs` 检查本例数学/资源。Python/Node 是可选制作工具，不是学生打开已交付 HTML 的要求。

分享整个包并保留素材身份；包内案例是相同参数重新表述，未包含教材题目/答案截图、原站身份、凭据或个人设置。素材见 [package-assets.md](package-assets.md)。没有额外指定开源许可证，不宣称第三方教材/图像版权全部取得。首次初始化保存的配置和实际实验目录不加入 Skill 发布仓库。
