# 验证应证明什么

## 模型：先算对，再看图

核对原题结果、量纲、符号与单位，以及一项非原题参数、一个临界状态和一个无效/超界状态。选至少一条符合本题的不变量，例如距离变化不影响平面镜最短镜长；不要把一个模型的不变量复制给另一个模型。连续过程还应检查时间起点、终点、暂停与重置。

图像验收需要反向检查：从渲染后的锚点和线段看是否真符合模型，例如入射/反射角、等距、受力方向、波节位置。模型函数算对不等于渲染用对；禁止把截图里明显不相交的线用“公式通过了”带过。

平面镜参考执行 `node scripts/verify_reference.mjs`；它只检查附带案例的纯计算函数。新题模型须加与物理行为有关的断言，不用测试匹配标题、CSS或固定公式文字来冒充物理验证。

## 实际交互

从指定 canonical 源构建后，用可用的受支持浏览器工具打开确切的最终产物，先确认整页正常启动，再真正拖动每个主要滑块/对象，检查数值、图像和反馈同步。模型函数、组件或最小 DOM 测试不覆盖整页初始化；当页面存在可选挂载点时，须核对缺少该挂载点不会使页面整体崩溃。有目标判定的实验覆盖初始、满足、不满足与重置；纯观察型实验检查代表性行为、临界和重置，不额外制造成功/失败判定。声明可拖动的点必须真的能拖，若仅支持滑块就在界面明确表现为滑块。

先改参数、选解释图层并展开说明，再切中文→英文→中文，确认参数、时间、图层与展开状态保留；查看题干全部小问、动态反馈、图例、单位和可访问名称是否都有翻译。语言切换后键盘焦点留在可见且合理的位置，收起的内容不应继续持有焦点。若切换的是另一套实验模式，则按设计重置播放、时间与选中项，不能让上一模式的状态泄漏。跨 HTML 导航与动态命中边界等功能按 [implementation-lessons.md](implementation-lessons.md) 中适用条目从实际最终页面核验；不要用固定假链接集合代替实际点击。

## 视觉与可用性

实际查看桌面与窄屏，观察原题和开始入口是否容易找到、标签是否遮挡人物/光线、画布是否裁切、控件是否掉到看不到的位置。用批准参考和当前截图逐项比对，写明必要的响应式变化。检查控制台错误、资源加载和基础键盘操作；若某工具或设备不可用，准确标记未检查，不将窄桌面窗口等同于手机实机。

如果解释会显示参考临界图而当前镜位未变，应直接注明“参考构图”；不能让没有覆盖反射点的镜片看起来反射成功。确认真实路径有方向箭头，虚像延长线没有传播箭头。

## 交付边界

分别记录“数学已验证”“浏览器实际操作”“画面已比对”“发布状态”，不要用一个总 PASS 覆盖未知项。浏览器不可用不必删除已完成结果，但只能报告源码/数学检查与未测项目。静态效果图不算运行结果；工具回执不算教学效果或素材权利证明。

分享包排除个人路径、源站 ID/账号、凭据、浏览器会话、Git历史和未授权教材截图。来源不明的图不默认可公开再分发，改绘图不冒称原图；用户拥有/已许可资产按实际授权使用。交付说明应足够让别人重新打开项目，不要求对方拥有作者的 Obsidian、工作区配置或私有插件。
