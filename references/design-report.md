# 实验设计报告：先看清将得到什么

报告是阶段 A 的实际交付物，不能只给文字计划，也不能在用户确认前先把实验做完。按本题需要保持简洁，下面是必需信息而非必须逐项堆成十个页面；可合并栏目，但分类、画面、交互、物理及确认点不能丢。

## 读题与入站定位

展示上传原题/来源身份、完整条件/小问、OCR或物理歧义。用自己的理解说明问题、所求及学生要观察/理解的关系。给出主分类、关联标签、理由/置信度、建议章节、实验中英标题与 slug；现站已有目录则明确复用哪一项。

说明怎么放到网站：主页是否只新增一个推荐卡片、目录在哪个分类增加条目、题页和实验的入口/返回路径、是否影响其他页。若是本地独立作品，说明相同分类用于本地目录，远端站点不改。没有源码或写入能力时，区分“拟集成位置”与“已经完成集成”。

## 模型与解题依据

列已知/所求、假设、手算结果和关键边界，不只给最终答案。用小表映射“物理量 → 学生可改变/只读 → 可见结果”，并指出至少一个值得对比的非原题或临界状态。说明选择连续模拟、构图解释或有限示意的理由；不同题型不要照搬镜子案例。

## 每个画面：效果图在上，方案在下

至少覆盖本题实际会出现的关键屏/状态：题页、主实验初始状态、一个重要变化或临界状态、解题/构图解释；已有主页仅展示受影响卡片/目录，必要时和题页合并。全新站再补主页。一个画面内多个状态可用并列图或局部放大，不为“逐屏”创造更多学生点击流程。

每张图下必须写清：

- 这屏有什么：题干、人物/器材、参数、读数、按钮和解释。
- 学生做什么 → 哪些图像/数值/反馈随之变化 → 哪些量保持。
- 怎样实现：复用/新生成位图与计算 SVG/Canvas、HTML控件各负责什么；锚点、遮罩、轨迹或向量来自哪个模型。
- 与前后画面的关系、返回方式、手机重排及中文/英文变化。

报告里的滑块、按钮、光线是效果示意，不声称可拖动已验证。视觉选定时直接继承；新构图仍展示具体画面。没有图像生成能力时，可用已有素材组合静态预览；若只能出线框或文字，标明未完成的视觉部分，交由用户决定是否补图/接受降级，不能继续进入制作。

## 操作与解题顺序

区分“学生进站路径”和“同一画布里的推理显示层”。前者尽量短；后者每层解释新增线/量为何有用，例如虚像连线、真实传播、相似三角形。列每个控件的名称、范围/初值、输入方式和可见反馈；未必要每题三个滑块，更不默认多关卡。静态观察型实验不用制造答对/答错。

参考临界图不能偷偷重设当前参数，无法发生的光路不能画成实际发生。时间过程说明改参数时是重启实验还是连续过程。中英切换应保留参数、时间、选中层与展开状态，报告可展示主要中英文案及长文本排布。

## 交付选择与确认点

继承初始化偏好，明确单实验/多实验目录、已有站/新站，以及默认自包含本地 HTML 和可选额外在线链接。列新增资产、依赖工具与可用能力、实际需要的检查，区分已手算核对与尚未进行的浏览器验收。在线能力和链接访问范围按当前宿主核验，不能把本机 localhost 地址当作可分享链接。

末尾给一个版本，如“实验设计报告 v1”，简列待确认的分类、页面/视觉、操作与交付方式，然后停下。可以这样写：“以上为本题设计报告 v1，效果图是静态预览；你确认后，我再实现并验证实验。”不能在这句话后继续调用 scaffold、生产脚本、目录写入或部署。用户要求修改时更新同一报告；确认后的细节修错不重开一串形式审批。
